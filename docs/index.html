Metadata Grounding: Let Your Coding Agent Search Your Org by Intent

Agentforce & AIDevOps & ToolingIntegration & APIs
  • The Metadata Grounding MCP Server (Beta) lets coding agents search a pre-indexed catalog of an org's metadata by natural-language intent, so they find existing components before building new ones.
  • It exposes three read-only tools, describe_metadata, search_metadata and query_metadata, following a describe, search, then query pattern across 70+ metadata types such as objects, fields, LWCs, Apex classes, flows and permission sets.
  • It is backed by Salesforce Catalog on Data 360, using a hybrid vector and keyword index. Incremental sync covers supported types, and a full refresh runs every 24 hours, so recent deployments can lag.
  • Two Pronto examples show it in use: a vague menu-page bug led to MenuBrowserController and the c__menuBrowser LWC, and a review-summary request led to the existing AgentSummarizeReviewsActions class, which was extended instead of rebuilt.
  • It returns metadata and properties, not source code, and it is not an exhaustive inventory. Agents must retrieve code via the CLI or Metadata API and should confirm a record with query_metadata before coding against it.

Runtime Behavior Anti-Patterns in Lightning Web Components

LWC / UIApex & CodeSecurity & Admin
  • This is the third post in the LWC anti-patterns series. It covers DOM access, async timing, lifecycle hooks, performance, and base component usage.
  • Don't use document.querySelector, innerHTML, or #id selectors, because LWC rewrites ids and scopes shadow DOM. Use this.template.querySelector or lwc:ref (this.refs.x) instead, and use lightning-formatted-rich-text for trusted rich HTML.
  • Don't use setTimeout to wait for data or re-renders. Use async/await for data, and use renderedCallback() with a guard flag for DOM work, since it fires after every render.
  • Don't read @api properties or touch the DOM in constructor() or connectedCallback(), because values and children aren't ready yet. Use connectedCallback, @wire, or renderedCallback, and avoid this.template.children.
  • Under Lightning Web Security, clone Apex/LDS data once on arrival before looping, and prefer plain objects and arrays over Set/Map for large collections.

Protect Your Salesforce Commerce API (SCAPI) from Bots and AI Agents with eCDN

Security & AdminIntegration & APIsReleases
  • The October 2026 B2C Commerce release makes the SCAPI zone (the eCDN zone in front of Commerce API traffic) manageable in Business Manager and the CDN API. One zone is shared across Dev, Staging, and Production and is managed from Production only.
  • The SCAPI zone supports custom firewall rules, rate limiting, IP access lists, analytics, and cache purge. It does not support WAF managed rulesets, mTLS, TLS 1.3 settings, HSTS, Page Shield, or Under Attack Mode, and the Crypto tab is read-only.
  • The new SCAPI Identity Header (SIH) lets you accept Shopper API traffic only from Managed Runtime. Enable the Managed Runtime SCAPI Request Identification feature per instance, then add a custom block rule on the instance's path segment (e.g. f_ecom_abcd_prd plus /shopper) after the locked managed allow rule. Start in Log mode before switching to Block.
  • Custom BFFs, mobile backends, and partner integrations can't present the SIH, so each needs its own allow rule with a server-side shared-secret header, placed above the block rule. SLAS hardening: Strict Client Auth requires an x-slas-client-auth header for private clients, but PWA Kit and Storefront Next don't send it yet, so enabling it for those clients breaks shopper login with 401s. SLAS also throttles refresh-token exchanges to 3 per 60 seconds, returning a 429 beyond that.
  • Two new fields work on every eCDN zone: Known Bot (cf.client.bot) and Verified Bot Category (cf.verified_bot_category, 17 categories such as AI Crawler, AI Search, AI Assistant, and Search Engine Crawler). Use them to rate limit AI traffic on expensive endpoints like product search (example: 30 requests per 60 seconds per IP, log first). They cover only Cloudflare-verified bots, so unverified or spoofed automation needs bot scores or a third-party bot manager.

Building Interactive UI with Headless Experience Layer

Agentforce & AILWC / UIIntegration & APIs
  • The Headless Experience Layer (HXL), part of the Headless Toolkit in AIforce, lets you define an interactive widget once in declarative JSON and render it natively in Agentforce and in MCP clients that support MCP Apps, such as Claude and ChatGPT.
  • HXL has three core concepts: Components (surface-aware UI primitives), Widgets (composed experiences, stored as a UiWidgetBundle under uiWidgets/<name>/ with a .uiwidget-meta.xml, a composition JSON, and an optional schema.json), and Custom Lightning Types (CLTs) that bind data shape to a widget through renderer.json.
  • Widgets are not LWC or React and contain no JavaScript. They use {!$attrs.x} placeholders and forEach/forItem for lists, and the data comes from an Apex invocable action, so existing sharing and field-level security still apply.
  • Agentforce needs one CLT typed to the Apex class, and the Agent Script output must set complex_data_type_name and is_displayable: True. MCP needs two nested CLTs (inner mirrors the Apex output, outer mirrors the actionName/isSuccess/outputValues envelope) with paths like {!$attrs.outputValues.reviews.averageRating}, plus a uiResource on the MCP server tool definition.
  • The beta supports two client actions, sendMessage and openLink. Agentforce may sometimes return follow-up answers as text instead of the card, so name the action explicitly in the subagent instructions. The HXL Playground previews can differ from live surfaces, so test on each target.

Agentforce Voice for Agent Script: Voice-Enabling Best Practices

Agentforce & AIApex & CodeDevOps & Tooling
  • Voice-enabling an Agent Script agent is not a rewrite: you enable Agentforce Voice in the org, add three voice blocks to the script, and retune the instructions for listeners.
  • The org must have Agentforce Voice turned on (it runs on Salesforce Voice with Telephony Providers). You can check by searching for Telephony under Add Connections in Agentforce Builder, and a free Developer Edition org currently doesn't support it.
  • The three required script blocks are a top-level `language` (default_locale), `connection telephony` (which makes it a voice agent), and `modality voice` (outbound persona_id and model.id, inbound filler_words_detection).
  • `language` must appear both at the top level and inside `modality voice`, because the persona_id resolves against a model and language and otherwise silently falls back to the default voice.
  • Supported voice models are eleven_v3_conversational, eleven_flash_v2_5, eleven_flash_v2 (English only) and kotoba (Japanese). The model can only be set in Script view, and the legacy flat voice_id format cannot pick a model.

Pro-Code Chunking of Data 360 Search Indexes for Agentforce

  • Native Data 360 chunking (section-aware, semantic passage extraction) works for clean content but breaks down on dense tables, multispeaker transcripts, and PII-laden documents in complex PDFs.

  • For tables, a structure-aware function detects markdown, grid and HTML tables, keeps each as a unit, and repeats column headers in every sub-chunk when a table exceeds the size limit; in the example, the agent went from being unable to interpret '42.1 35.8 22.4...' to correctly reporting 87.9% YoY growth and a 28.1% operating margin for AI & Automation.
  • For multispeaker dialogue, a sliding window (WINDOW_SIZE=6 turns, STRIDE=3, MAX_CHUNK_CHARS=1500) preserves speaker attribution and timestamps and keeps questions co-located with answers, fixing native chunks where speakers and topics were mashed together.
  • Caveat from the author: the sample code relies on regex heuristics, covers only happy-path inputs, and can produce false positives and negatives, so production use needs hardening; the post also covers a third use case, masking exposed PII, though the provided text is truncated before it.

  • Salesforce Hosted MCP Server security is built in layers: authentication, authorization, permission control (object/field level), and logging for audit.
  • Authentication supports only the OAuth 2.0 authorization code flow through an External Client App (ECA). Shared service or integration-user sessions are called an anti-pattern, and machine-to-machine flows are not planned.

  • All MCP servers are disabled by default, so enable only the ones you want to expose. Tool annotations (for example destructive or idempotent hints) help agents behave safely, but clients are not required to honor them.

ReleasesDevOps & ToolingIntegration & APIs
  • The Omnistudio Migration Assistant (OMA), a Salesforce CLI plugin, automates moving Flexcards, Omniscripts, Data Mappers and Integration Procedures from managed package runtimes (Vlocity Industries or Omnistudio Foundation) to the Omnistudio standard runtime.
  • Salesforce cites internal testing in which execution averaged 2112 ms on the standard runtime versus 5061 ms on a managed package runtime, with claimed gains of up to 5x for Flexcards, 4x for Integration Procedures, 3x for Data Mappers and 2x for Omniscripts.
  • Migration has three phases (development, validation, production). The first runs OMA in Assess mode, fixes flagged issues until the report is clean, then runs Migrate mode. The tool is installed with `sf plugins install @salesforce/plugin-omnistudio-migration-tool@2.0.0-rc.57`, and the commands are `sf omnistudio:migration:assess` and `sf omnistudio:migration:migrate` with `-u` and `-a`.
  • Prerequisites and caveats: upgrade to Vlocity Industries managed package Winter '26 or later first; never migrate directly in production; and do not uninstall the package afterward, because existing workflows may still rely on its schema.
  • OMA is said to cut manual effort by 95%, but older Angular-based components and industry-specific object mappings still need manual work. Customers already on the standard runtime need no action, and Omnistudio has been package-free for new customers since Summer '25.
