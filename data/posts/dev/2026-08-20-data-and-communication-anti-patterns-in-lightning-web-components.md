- This is the second post in a series on LWC anti-patterns; it covers the @wire service, public @api properties, and event handling, following a first post on security and Lightning Web Security.
- The central mental model is that @wire is a subscription, not a one-time fetch. Adapters can emit multiple times (cache, network, other components' edits), so handlers must be idempotent and derive all state from the latest emission.
- Wire data is immutable, so copy it into a local property before mutating. Never change wire config inside renderedCallback(), which causes an infinite render loop. Don't assume multiple adapters fire in order, and don't read wire data in connectedCallback().
- For LDS caching, use notifyRecordUpdateAvailable() after imperative Apex writes instead of refreshApex(), which is deprecated for LDS adapters like getRecord. Don't mix Apex and LDS for the same record, and don't add dummy optionalFields to bust the cache.
- Other wire fixes: import field tokens from @salesforce/schema, use full relationship paths such as Case.Account.Name in getRecord, and gate dependent data with undefined reactive properties instead of promise chains. Use top-level '$prop' config values instead of swapping a config object, and use imperative Apex rather than @wire for DML.
